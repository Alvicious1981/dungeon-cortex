# UI-01 — Design System Normalization

## Branch
`claude/ui-01-design-normalization` (or the isolated non-master branch Desktop already created from `origin/master`).

## Prerequisite
None beyond a verified clean base derived from current `origin/master`.

## UI_SPEC anchor
`docs/DESIGN.md` §2 (tokens), §5 (component states), §6 (motion); `docs/UI_SPEC.md` §7. Cross-cutting hardening, not a new
surface. Product scope does not change.

## Objective
Normalize the main UI surfaces to the existing Dungeon Cortex design system without changing functional behavior.

## Repository facts (verified 2026-10-01 — re-verify in preflight)
- `app/globals.css` defines the `--dc-*` tokens (107 occurrences). The only shared primitives are
  `components/ui/Button.tsx`, `Panel.tsx` and `StatusMessage.tsx`, covered by `tests/components/UiPrimitives.test.tsx`.
- **`components/downtime/HavenHUD.tsx` has no importer.** It is a surface of the downtime subsystem that
  `docs/DECISION_5E_SRD_API.md` §8 removed. Do not normalize or revive it unless re-verification finds a live caller; report
  that it is unrendered.
- `package.json` has no motion library. Do not add one (`docs/DESIGN.md` §6 sets 140/220 ms, `transform`/`opacity`).
- Interface copy is Spanish.

## Implement
- Replace decorative hardcodes (colours, radii, spacing, durations) with semantic `--dc-*` tokens where the equivalence is clear.
- Reuse Button / Panel / StatusMessage where behavior stays unchanged.
- Preserve keyboard access, focus, reduced motion, labels, roles and 44 px targets.
- Keep a domain-specific colour only when no semantic token fits, and note why.
- Prefer one surface per commit so the diff stays reviewable. If it stops being reviewable in one PR, `STOP-SCOPE` and propose a split.

## Do not
- Redesign layouts materially.
- Change mechanics, APIs or the database.
- Add dependencies or a motion library.
- Touch `components/downtime/HavenHUD.tsx` (see facts) or the disabled wilderness surfaces.

## Targeted verification
Run the existing tests of every touched surface, for example `tests/components/UiPrimitives.test.tsx`,
`tests/components/CharacterSheetVTT.test.tsx`, `tests/components/DungeonMapVTT.test.tsx`,
`tests/components/combat-hud-keybinds.test.tsx`, with `pnpm exec vitest run --maxWorkers=2 <paths>`.
Add a regression test only where behavior could change by accident, and falsify it (UI-WORKFLOW §6).

## Acceptance
- Behavior unchanged; no second visual system.
- No accessibility or responsive regression at the four reference sizes.
- Common acceptance in [UI-WORKFLOW.md](../UI-WORKFLOW.md) §8; validation per §6.
