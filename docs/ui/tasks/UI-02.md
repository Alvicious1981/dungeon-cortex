# UI-02 — Combat HUD Evolution

## Branch
`claude/ui-02-combat-hud` (or the isolated non-master branch Desktop already created from `origin/master`).

## Prerequisite
UI-01 is present in `origin/master` (`git log origin/master --oneline --grep "^UI-01:"`). Otherwise `STOP-PREREQ`, unless the
START prompt records a maintainer deviation ([UI-WORKFLOW.md](../UI-WORKFLOW.md) §3).

## UI_SPEC anchor
`docs/UI_SPEC.md` §2 P0.6 (combat already backed by the backend), §3 Contexto, §5, §8. P0.

## Objective
Evolve the existing Combat HUD without replacing it.

Keep:
- combatants;
- initiative;
- HP;
- conditions;
- active turn;
- current actions;
- pending state;
- `playerDown`;
- the hardened keyboard shortcuts.

Prepare or add compatible presentation for:
- player health;
- player resources, only when real data exists;
- clearer spatial hierarchy;
- an area for the UI-03 Action Bar.

## Repository facts (verified 2026-10-01 — re-verify in preflight)
- `components/combat/CombatHUD.tsx` owns the F1 → Attack and F2 → End Turn `keydown` listener and ignores text-entry
  controls (`isContentEditable`) and open dialogs (`dialog`, `role="dialog"`, `aria-modal`).
- `MASTER_ARCH_GUIDE.md` §5.2–§5.3: `CombatHUDController` and `ConsequenceLog` read `COMBAT_CONSEQUENCE.payload.targets[]`
  directly, with no flat-field fallback; quick controls expose only backend-resolved `Attack` and `End Turn`.
- `MASTER_ARCH_GUIDE.md` §4.4: the backend decides whether it is the player's turn and what the player may do, including the
  downed player's `Death Save` / `Wait` actions. The HUD presents that; it does not decide it.
- Existing tests: `tests/components/combat-hud-keybinds.test.tsx`, `combat-hud-downed.test.tsx`,
  `hud-attack-target-selection.test.tsx`, `combat-state.test.ts`, `hit-points.test.ts`, `InitiativeTracker.test.tsx`,
  `MacroDeck.test.tsx`, `macro-deck-death-saves.test.tsx`.

## Critical regression coverage
Verify, with the existing tests or new falsified ones:
- active turn;
- HP values;
- conditions;
- pending disables actions;
- `playerDown`;
- F1 / F2;
- repeat and modifier-key handling;
- shortcuts ignored in text-entry controls;
- shortcuts ignored behind active dialogs and modals.

## Do not
- Change combat resolution or `targets[]` handling.
- Invent resources the data does not carry.
- Change the available actions or add a quick control the backend does not resolve.
- Extract the full Action Bar yet (UI-03).

## Acceptance
- One Combat HUD remains authoritative; keyboard hardening and combat behavior are unchanged; layout is responsive at the
  four reference sizes.
- Common acceptance in [UI-WORKFLOW.md](../UI-WORKFLOW.md) §8; validation per §6.
