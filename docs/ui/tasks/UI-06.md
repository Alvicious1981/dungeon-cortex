## UI_SPEC anchor
`docs/UI_SPEC.md` §2 **P2.1**: spatial inventory editing. This is a P2 task. State that tier in the plan. It must not displace or
degrade the P1 list view, and it is the first task the maintainer may defer.

## Objective
Evolve the existing inventory toward a spatial presentation without creating a third inventory authority.

## Repository facts (verified 2026-10-01 — re-verify in preflight)
- `InventoryItem` in `prisma/schema.prisma` has `quantity`, `properties` (JSON), `equippedSlot` and `indexSlug`. It has **no**
  position, dimensions, grid size or capacity, and nothing validates placement.
- The inventory UI is `components/character/InventoryPanel.tsx`, `components/character/sheet/InventoryGrid.tsx` and
  `components/inventory/InventoryItem.tsx`, used by `CharacterSheetVTT`. Determine whether `InventoryGrid` is only a visual
  layout over the flat list or already carries spatial data.
- Adding persisted spatial data is a Prisma change. `AGENTS.md`: migrations are written by hand and never run by the agent, and
  the schema is not a UI-task decision.

## Discover first
Determine whether the real model provides grid size, position, dimensions, capacity or placement validation. The expected
answer today is **no**. In that case do not invent Prisma or backend data to satisfy the concept.

## Presentation
Support a controlled representation of, when the data is real:
- position and dimensions;
- quantity;
- equipped;
- tooltip;
- selected;
- valid and invalid destination.

The old guide sizes (1×1, 1×2, 2×2, 2×3, 1×4) are examples, not canonical rules.

When spatial data is absent, deliver a controlled presentational contract (props for items, optional placement, callbacks and
validation results supplied by the caller) with the existing list as the live fallback. If the maintainer needs it persisted,
`STOP-AUTHORITY`: that is a separate backend decision and Issue.

## Interaction
If drag is implemented:
- no new dependency;
- keep the item within the usable surface;
- a rejected move returns safely;
- include the non-drag alternative: select item → select destination → confirm.

## Feedback
Invalid placement carries text, not only red/green. The reason comes from the caller's validation, never from a rule written in React.

## Fallback
Preserve the existing usable inventory when spatial data is unavailable.

## Targeted tests
Dimensions/presentation where supported, selection, valid/invalid destination, callbacks, fallback, keyboard, quantity, tooltip
and equipped. Run with `pnpm exec vitest run --maxWorkers=2 <paths>`; falsify what you add.

## Acceptance
- One source of truth; accessible fallback; no invented mechanics; no new dependency; no schema change.
- Common acceptance in [UI-WORKFLOW.md](../UI-WORKFLOW.md) §8; validation per §6.
