## Objective

## Repository facts (verified 2026-10-01 — re-verify in preflight)
- No `AiNarrativeTerminal` exists. The real surface is `app/campaign/[id]/StoryLog.tsx` (history) and
  `app/campaign/[id]/ActionInput.tsx` (player intent), with `components/combat/GameEventHandler.tsx` and
  `components/combat/ConsequenceLog.tsx` for events. Mobile navigation: `components/campaign/CampaignMobileNav.tsx`.
- `ActionInput` owns the **only** campaign-action SSE fetch and frame parser (`MASTER_ARCH_GUIDE.md` §5.3); correlated requests go
  through `lib/events/action-transport.ts`. Do not add a second fetch or parser.
- Narration is buffered and validated before a single text chunk is emitted (`AGENTS.md`; `docs/NARRATIVE_SAFETY.md`). A
  completed action receipt means the mechanical outcome finished, not that narration was delivered or persisted.
- Tests: `tests/components/StoryLog.test.tsx`, `ActionInput.test.tsx`, `action-input-downed.test.tsx`, `CampaignChrome.test.tsx`.

## Discover before designing
Locate the actual narration/chat UI, the history, the streaming, the player action input, the APIs and hooks, and the tests.
Decide:
- existing UI → evolve it;
- state/backend but weak UI → add a UI consumer;
- no usable contract → a presentational controlled component, only if useful and safe.

## Do not
- Invent AI architecture, endpoints, persistence or a streaming protocol.
- Touch `lib/ai/**`, `lib/narrative/**` or the action route. This task is presentation.
- Create a second input or a second SSE consumer.

## Presentation
Structurally distinguish, with labels and structure and not colour alone:
- narration;
- the player's intent;
- mechanical information confirmed by the backend;
- system messages and events where appropriate;
- dialogue / speaker, only if the data really carries it.

Mechanical text is direct; narration may be literary. Never present an operation as confirmed before the authoritative response.

## Behavior
- history;
- stable scrolling (a new message must not yank a reader who scrolled up);
- pending;
- error, with what happened and what to do;
- degraded or lost connection;
- minimize/expand if useful;
- the existing input integration.

No typewriter effect and no artificial delay of text (`docs/DESIGN.md` §6).

## Targeted tests
Narrative, mechanical and dialogue distinction, empty history, pending, error, minimize/expand and accessibility (landmarks,
`aria-live`, names). Run with `pnpm exec vitest run --maxWorkers=2 <paths>`; falsify what you add.
